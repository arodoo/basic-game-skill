# Godot Skill

A lightweight project scaffold for Godot-focused game development workflows, architecture decisions, testing habits, and documentation conventions.

This repository is intentionally simple. It is not a polished framework or a finished game template. It is a practical base that can be improved, replaced, or expanded as the project grows.

## Why this exists

The goal is to keep the project easy to understand and easy to evolve.

It brings together a few useful ideas:

- clear game architecture boundaries
- testing patterns for gameplay and logic
- a documentation structure that is easier to maintain
- agent instructions to keep work consistent

The important point is clarity, not perfection.

## Project structure

- `AGENTS.md` — top-level instructions for AI-assisted work
- `agents/` — reusable prompts and instruction files
- `docs/` — documentation organized by purpose

## Documentation

The docs folder follows a simple intent-based structure:

- `docs/explanation/` — why decisions exist
- `docs/how-to/` — practical procedures
- `docs/reference/` — definitions and API-like reference material
- `docs/tutorials/` — learning-oriented guides

This structure is meant to help the project stay understandable even as it grows.

## What this repository is not

This is not a production-ready engine, not a commercial framework, and not a closed system that cannot be changed.

It is a starting point for thinking and organizing work in a clean way.

## How to use it

You can:

- keep the structure and adapt it
- remove rules that do not fit your workflow
- expand the docs with real project decisions
- rewrite conventions as the game evolves

A repo like this should be useful, not rigid.

## Final note

If a rule is too strict, relax it. If a doc is incomplete, improve it. If the architecture no longer fits, change it.

This project is meant to be a durable foundation, not a cage.
